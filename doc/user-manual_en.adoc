== About this manual

ERD9 is a modeling tool for designing database structures by drawing tables (entities) and the relationships between them.
It runs directly in a web browser, and the same program is also available as a Windows executable (the desktop app).

This manual describes every feature of ERD9 with screenshots.
The examples use an online shopping mall model with eight tables: customer, order, product, payment, delivery, review and so on.

NOTE: The example model uses Korean logical names (entity and attribute names, which become table and column comments), and the Windows file dialogs were captured on Korean Windows. The menus and dialogs of ERD9 itself are in English. Where a Korean word matters in the text, its meaning is given in parentheses.

[cols="1,3",options="header"]
.Web version and desktop app
|===
| Edition | Description

| Web version
| Runs in a web browser (Chrome, Firefox, Edge). There is no login and no server storage; documents are stored in the browser (IndexedDB).

| Desktop app
| Saves and opens documents as `.erd9` files in JSON format (see <<desktop-files>>). In addition to every feature of the web version, the *Database* menu (Forward Engineering, Reverse Engineering, Compare and Merge) connects directly to database servers. A web browser cannot connect to a database server directly, so this menu exists only in the desktop app.
|===

IMPORTANT: Documents of the web version are stored only in the browser you are using. On a shared PC, delete your documents after use, and keep important documents on your PC with menu:Files[Export to Json]. The desktop app saves documents as `.erd9` files in a location you choose, so you can back them up or move them to another PC by copying the files.

Select the *Entity* tool on the toolbar and click an empty area of the canvas to create an empty entity.

=== Selecting an entity and the shape menu

Click an entity to select it. A shape menu appears at its top left.

* ⓧ : delete the selected shape (same as the kbd:[Del] key)
* ⓔ : open the edit dialog (same as double-clicking)

To select several entities, click them while holding kbd:[Shift], or drag a rectangle from an empty area.
kbd:[Ctrl+A] selects all shapes.

TIP: When only one entity is selected, drag one of its column rows up or down to change the column order.

Click a Data Type cell and type to list the matching data types of the current DBMS.

==== Indexes and CHECK constraints

Click btn:[Index / Check] to switch to the index editor. Click it again to return to the column list.

.Indexes and CHECK constraints
image::entity-index.png[Index / Check]

Creating an index::
. Click the columns for the index in the column list on the left. The selected columns appear in the middle; drag them to change the order.
. Enter the *Index Name* (at least 5 characters). For a unique index, select *Unique*.
. Click btn:[add]. If an index with the same name exists, it is updated.
. Click an index in the list to edit it again, or click the `x` in front of it to delete it.

Creating a CHECK constraint::
. Enter the *Name* and the *Expression* (for example `PRICE >= 0`).
. Click btn:[add]. Click an item in the list to edit it, or click `x` to delete it.

== Relationships

=== Creating a relationship

Select a relationship tool (identifying or non-identifying), click the parent entity and then the child entity.
The primary key of the parent entity is added to the child entity as a foreign key (FK).

* *Identifying relationship (solid line)* : the foreign key becomes part of the child's primary key (shown as `PF`).
* *Non-identifying relationship (dashed line)* : the foreign key becomes a regular column of the child (shown as `FK`).

.A non-identifying relationship from CUSTOMER to COUPON (CUST_NO added to COUPON)
image::relation-new.png[Creating a non-identifying relationship]

=== Editing a relationship

Click a relationship line to select it, or double-click it to open the *Relationship* dialog.

.A selected relationship line
image::relation-selected.png[Selected relationship]

.Relationship dialog
image::relation-dialog.png[Relationship dialog]

[cols="1,4",options="header"]
|===
| Field | Description

| Cardinality
| One To One (1:1) or One To Many (1:N)

| Optionality
| Whether the parent and the child are mandatory or optional. The symbols at the ends of the line change.

| FK Constraint Name
| Name of the foreign key constraint. If left empty, the internal ID is used.

| ON DELETE / ON UPDATE
| Referential actions (NO ACTION, CASCADE, SET NULL, ...). Options the selected DBMS does not support are left as comments in the generated DDL.

| Relationship Name
| A name shown on the line (for example places, has)

| Automatic route
| Draws the line automatically around other tables. After moving the line by hand, turn this on again to return to the automatic route.
|===

TIP: Drag the middle of a relationship line to move its bend, or drag an end to slide it along the edge of the entity.

=== Self-referencing relationship

Click the same entity twice with a relationship tool to create a self-referencing relationship (for example a parent category, or an employee's manager).
The key is added as a column that starts with `PARENT_` and allows NULL.

=== Import from DDL

Builds an ERD by analyzing DDL (CREATE TABLE and so on). It imports tables, column comments, primary keys, relationships (foreign keys), indexes, CHECK constraints, views and sequences.
MariaDB, PostgreSQL and MS-SQL statements are analyzed with an SQL parser; Oracle and statements the parser cannot read are analyzed with pattern matching.

. Copy the DDL to the clipboard.
. Open menu:Add-ons[Import from DDL] and click btn:[Paste]. Select the DBMS of the DDL.
+
.SQL tab: the pasted DDL
image::addon-importddl-sql.png[Import from DDL - SQL]
. Click btn:[Preview] to see the result of the analysis in the *Preview* tab.
+
.Preview tab: the result for each table
image::addon-importddl-preview.png[Import from DDL - Preview]
. Click btn:[Run (Import from DDL)], or btn:[Run (Import from Preview result)] in the Preview tab, to create the entities and relationships. What was done is shown in the *Log* tab.
+
.Log tab
image::addon-importddl-log.png[Import from DDL - Log]

TIP: Imported entities are placed one after another without overlapping. Arrange them with <<auto-layout>>.

[[domains]]
==== Domains

A domain is a data type, default value and NOT NULL setting shared by many columns. Changing a domain updates every column that uses it. *Used* is the number of columns that use the domain.

.Domains tab
image::std-domains.png[Domains]

=== Compare and Merge

Compares the ERD with the database, lists every difference (tables, views, sequences), and applies each one in the direction you choose.
In the example below, a `BIRTH_DT` column was added to `CUSTOMER` in the shopping mall ERD used for Forward Engineering, while a `product.ORIGIN_NM` column and a `faq` table were added to the database in the meantime.

Tables, columns, views and sequences are matched by name, ignoring case. Even when the database returns table names in lower case, as MariaDB on Windows does, they are matched with the upper-case names of the ERD, and the scripts use the actual names in the database. Notations the database rewrites (integer display widths such as `INT(11)`, the default `current_timestamp()`, quotes and parentheses in view queries) are not reported as differences.

. Open menu:Database[Compare and Merge], enter the connection settings and click btn:[Compare].
+
.Compare and Merge: the differences
image::db-sync.png[Compare and Merge]
. Choose the direction of each item in *Apply*. btn:[All ERD → DB], btn:[All DB → ERD] and btn:[Skip all] change all of them at once.
+
[cols="1,2,2",options="header"]
|===
| Status | ERD → DB | DB → ERD
| ERD only | Create in DB | Delete from ERD
| DB only | Drop from DB | Add to ERD
| Different | ERD → DB (runs an ALTER script) | DB → ERD (updates the ERD)
|===
+
Items set to *Skip* are not applied.
*Script to run on the database* shows the ALTER script for the ERD → DB items.
+
.Directions: customer ERD → DB, faq and product DB → ERD (names are shown as the lower-case names of the database)
image::db-sync-direction.png[Choosing directions]
. Click btn:[Apply] and confirm. The script is run on the database and the ERD is updated, and then the two are compared again to show any remaining differences.
+
.After applying: no differences
image::db-sync-done.png[Result]
+
.The faq table and PRODUCT.ORIGIN_NM added to the ERD (keeping the ERD's names), and customer.BIRTH_DT added to the database
image::db-sync-result.png[ERD after applying]

IMPORTANT: Because items are matched by name, a renamed column appears as dropped and added. If the database script fails, the ERD is not changed; updating the ERD clears the undo history. Always review the script and back up the database before applying changes to a production database.

[appendix]
== Frequently asked questions

Where are documents stored?::
The web version stores them in the browser's internal storage (IndexedDB). To move them to another PC or back them up, use menu:Files[Export to Json]. The desktop app saves them to `.erd9` files in the location you choose.

Is there no Database menu in the web version?::
A web browser cannot connect to a database server directly, so the Database menu exists only in the desktop app. In the web version, you can exchange DDL with <<import-ddl>>, Generate DDL and Compare ERD / ALTER Script.

Can I bring back an entity I deleted by mistake?::
Press kbd:[Ctrl+Z] to undo. If the document was saved, you can also restore an earlier version in menu:Files[History].
