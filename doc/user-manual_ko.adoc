== 이 매뉴얼에 대하여

ERD9는 테이블(엔터티)과 그 사이의 관계를 그림으로 그리면서 데이터베이스 구조를 설계하는 모델링 도구입니다.
웹 브라우저에서 바로 사용할 수 있고, 같은 프로그램을 Windows 실행 파일(데스크톱 앱)로도 사용할 수 있습니다.

이 매뉴얼은 ERD9의 모든 기능을 화면과 함께 설명합니다.
화면의 예제는 온라인 쇼핑몰 모델(고객, 주문, 상품, 결제, 배송, 리뷰 등 8개 테이블)을 사용합니다.

[cols="1,3",options="header"]
.웹 버전과 데스크톱 앱
|===
| 구분 | 설명

| 웹 버전
| 웹 브라우저(Chrome, Firefox, Edge)에서 실행합니다. 로그인과 서버 저장이 없으며 문서는 브라우저(IndexedDB)에 저장됩니다.

| 데스크톱 앱
| 문서를 JSON 형식의 `.erd9` 파일로 저장하고 엽니다(<<desktop-files>> 참조). 웹 버전의 모든 기능에 더해 *Database* 메뉴(Forward Engineering, Reverse Engineering, Compare and Merge)로 데이터베이스 서버에 직접 연결할 수 있습니다. 웹 브라우저는 데이터베이스 서버에 직접 연결할 수 없으므로 이 메뉴는 데스크톱 앱에만 있습니다.
|===

IMPORTANT: 웹 버전의 문서는 사용 중인 브라우저에만 저장됩니다. 공용 PC에서는 사용 후 문서를 삭제하고, 중요한 문서는 menu:Files[Export to Json]으로 PC에 따로 보관하십시오. 데스크톱 앱은 문서를 사용자가 고른 위치에 `.erd9` 파일로 저장하므로, 파일을 복사해서 백업하거나 다른 PC로 옮길 수 있습니다.

== 엔터티

=== 엔터티 만들기

도구 모음에서 *엔터티* 도구를 선택하고 캔버스의 빈 곳을 클릭하면 빈 엔터티가 만들어집니다.

.새로 만든 엔터티
image::entity-new.png[새 엔터티]

엔터티를 더블 클릭하면 *Entity* 다이얼로그가 열립니다.
테이블 이름(물리명)과 엔터티 이름(논리명)을 입력하고, 컬럼 목록에 컬럼을 입력한 뒤 btn:[Save]를 누릅니다.

.새 엔터티에 컬럼 입력
image::entity-new-dialog.png[새 엔터티 입력]

=== 엔터티 선택과 도형 메뉴

엔터티를 클릭하면 선택되고 왼쪽 위에 도형 메뉴가 나타납니다.

* ⓧ : 선택한 도형 삭제 (kbd:[Del] 키와 같음)
* ⓔ : 수정 다이얼로그 열기 (더블 클릭과 같음)

.선택된 엔터티와 도형 메뉴
image::entity-selected.png[선택된 엔터티]

여러 엔터티를 선택하려면 kbd:[Shift]를 누른 채 클릭하거나, 빈 곳에서 마우스를 끌어 사각형으로 선택합니다.
kbd:[Ctrl+A]는 모든 도형을 선택합니다.
선택한 도형을 끌면 함께 이동합니다.

TIP: 하나만 선택된 엔터티의 컬럼 줄을 위아래로 끌면 컬럼 순서를 바꿀 수 있습니다.

==== 데이터 타입 입력

Data Type 셀을 클릭하고 글자를 입력하면 현재 DBMS의 데이터 타입 중 일치하는 항목이 나타납니다.
kbd:[↑] / kbd:[↓] 로 고르고 kbd:[Enter]를 누릅니다.
자릿수가 필요한 타입(`VARCHAR (n)` 등)은 괄호 안에 커서가 놓이므로 자릿수를 이어서 입력합니다.

==== 인덱스와 CHECK 제약조건

btn:[Index / Check]를 누르면 인덱스 편집 화면으로 바뀝니다. 다시 누르면 컬럼 목록으로 돌아갑니다.

.인덱스와 CHECK 제약조건
image::entity-index.png[Index / Check]

인덱스 만들기::
. 왼쪽 컬럼 목록에서 인덱스에 넣을 컬럼을 클릭합니다. 선택한 컬럼은 가운데에 표시되며, 끌어서 순서를 바꿀 수 있습니다.
. *Index Name* 을 입력합니다(5자 이상). 고유 인덱스는 *Unique* 를 선택합니다.
. btn:[add]를 누릅니다. 같은 이름이 있으면 수정됩니다.
. 목록의 인덱스를 클릭하면 다시 편집하고, 앞의 `x` 를 클릭하면 삭제합니다.

CHECK 제약조건 만들기::
. *Name* 과 *Expression* (예: `PRICE >= 0`)을 입력합니다.
. btn:[add]를 누릅니다. 목록의 항목을 클릭하면 편집하고, `x` 를 클릭하면 삭제합니다.

== 관계

=== 관계 만들기

관계 도구(식별, 비식별)를 선택하고 부모 엔터티를 클릭한 뒤 자식 엔터티를 클릭합니다.
부모 엔터티의 기본키가 자식 엔터티에 외래키(FK)로 추가됩니다.

* *식별 관계(실선)* : 외래키가 자식의 기본키가 됩니다(`PF` 로 표시).
* *비식별 관계(점선)* : 외래키가 자식의 일반 컬럼이 됩니다(`FK` 로 표시).

.CUSTOMER에서 COUPON으로 비식별 관계를 만든 결과 (COUPON에 CUST_NO 추가)
image::relation-new.png[비식별 관계 만들기]

=== 관계 수정

관계선을 클릭하면 선택되고, 더블 클릭하면 *Relationship* 다이얼로그가 열립니다.

.선택된 관계선
image::relation-selected.png[선택된 관계]

.Relationship 다이얼로그
image::relation-dialog.png[Relationship 다이얼로그]

[cols="1,4",options="header"]
|===
| 항목 | 설명

| Cardinality
| One To One(1:1) 또는 One To Many(1:N)

| Optionality
| 부모와 자식이 필수(Mandatory)인지 선택(Optional)인지 지정합니다. 관계선 끝의 기호가 바뀝니다.

| FK Constraint Name
| 외래키 제약조건 이름. 비워 두면 내부 ID를 사용합니다.

| ON DELETE / ON UPDATE
| 참조 동작(NO ACTION, CASCADE, SET NULL 등). 선택한 DBMS가 지원하지 않는 옵션은 생성된 DDL에 주석으로 남습니다.

| Relationship Name
| 관계선에 표시할 이름(예: places, has)

| Automatic route
| 다른 테이블을 피해 자동으로 선을 그립니다. 선을 직접 옮긴 뒤 이 항목을 다시 켜면 자동 경로로 돌아갑니다.
|===

TIP: 관계선의 가운데를 끌면 꺾이는 위치가 바뀌고, 끝 부분을 끌면 연결 위치가 엔터티의 변을 따라 이동합니다.

기본키는 `PARENT_` 로 시작하는 NULL 허용 컬럼으로 추가됩니다.

=== Compare and Merge

ERD와 데이터베이스를 비교해서 차이(테이블, 뷰, 시퀀스)를 모두 보여주고, 항목마다 원하는 방향으로 반영합니다.
아래 예는 Forward Engineering에 사용한 쇼핑몰 ERD에서 `CUSTOMER` 에 `BIRTH_DT` 컬럼을 추가하고, 그 사이 데이터베이스에는 `product.ORIGIN_NM` 컬럼과 `faq` 테이블이 추가된 경우입니다.

테이블과 컬럼, 뷰, 시퀀스는 이름으로 대응시키며 대소문자는 구분하지 않습니다. Windows의 MariaDB처럼 데이터베이스가 테이블 이름을 소문자로 돌려주어도 ERD의 대문자 이름과 같은 테이블로 보며, 스크립트에는 데이터베이스의 실제 이름을 사용합니다. 데이터베이스가 다시 써서 돌려주는 표기(정수의 표시 너비 `INT(11)`, 기본값 `current_timestamp()`, 뷰 쿼리의 따옴표와 괄호)도 차이로 보지 않습니다.

. menu:Database[Compare and Merge]를 열고 연결 정보를 입력한 뒤 btn:[Compare]를 누릅니다.
+
.Compare and Merge: 차이 목록
image::db-sync.png[Compare and Merge]
. 항목마다 *Apply* 에서 반영 방향을 고릅니다. btn:[All ERD → DB], btn:[All DB → ERD], btn:[Skip all]로 한꺼번에 바꿀 수 있습니다.
+
[cols="1,2,2",options="header"]
|===
| 상태 | ERD → DB | DB → ERD
| ERD only (ERD에만 있음) | Create in DB (DB에 생성) | Delete from ERD (ERD에서 삭제)
| DB only (DB에만 있음) | Drop from DB (DB에서 삭제) | Add to ERD (ERD에 추가)
| Different (다름) | ERD → DB (ALTER 실행) | DB → ERD (ERD 수정)
|===
+
모든 항목에서 *Skip* 을 고르면 반영하지 않습니다.
*Script to run on the database* 에 ERD → DB 항목의 ALTER 스크립트가 표시됩니다.
+
.반영 방향 선택: customer는 ERD → DB, faq와 product는 DB → ERD (이름은 데이터베이스의 소문자 이름으로 표시)
image::db-sync-direction.png[반영 방향 선택]
. btn:[Apply]를 누르고 확인하면 데이터베이스에 스크립트를 실행하고 ERD를 수정한 뒤, 다시 비교해서 남은 차이를 보여줍니다.

[appendix]
== 자주 묻는 질문

문서는 어디에 저장되나요?::
웹 버전은 브라우저 내부 저장소(IndexedDB)에 저장됩니다. 다른 PC로 옮기거나 백업하려면 menu:Files[Export to Json]을 사용하십시오. 데스크톱 앱은 사용자가 고른 위치의 `.erd9` 파일에 저장합니다.

웹 버전에는 Database 메뉴가 없나요?::
웹 브라우저는 데이터베이스 서버에 직접 연결할 수 없으므로 Database 메뉴는 데스크톱 앱에만 있습니다. 웹 버전에서는 <<import-ddl>>와 Generate DDL, Compare ERD / ALTER Script로 DDL을 주고받을 수 있습니다.

실수로 지운 엔터티를 되살릴 수 있나요?::
kbd:[Ctrl+Z] 로 되돌릴 수 있습니다. 저장한 문서라면 menu:Files[History]에서 이전 버전을 복원할 수도 있습니다.
